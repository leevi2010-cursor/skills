# 客户资料更新规则

本规则说明怎样把录音里已经确认的信息写入客户资料表。目标是先查重，再补齐唯一的原记录；确认没有对应记录时自动新建，但不把销售建议或 AI 判断写进客户资料。

## 允许范围

- 只更新配置中指定的客户资料表。
- 每份录音先寻找能够明确对应的现有客户记录；确认不存在且身份资料足够时，自动新建一条。
- 只写逐字稿、原录音、用户说明或现有业务记录能够直接证明的事实。
- 不重复新建客户，不新建或删除表格、字段、选项和视图，不删除记录，不修改权限。
- 不把完整逐字稿、客户联系方式或本机路径放进分析报告、普通日志或 Git 仓库。联系方式只可在匹配原记录和写入联系方式字段时使用。

## 找到原客户记录

按以下顺序寻找，满足一项后仍要确认结果只有一条：

1. 用户或上游记录明确提供的飞书 `record_id`。
2. 现有客户资料中的“客户 ID”。
3. 已确认且完整一致的联系方式。
4. 两项以上能互相印证的信息，例如已确认客户姓名、项目地址、到店日期或接待销售。

客户姓名或称呼单独相同不够可靠。用户明确选择的 `record_id` 可以直接确定原记录；从其他来源取得的 `record_id` 仍要用至少一项客户事实核对。查询时只选择本次判断需要的字段，并优先在飞书端使用精确条件筛选，不把整张客户表下载到本地。

查询结果按以下方式处理：

- **0 条**：先用最强的已确认信息重新查重。仍为 0 条且满足下方最低识别要求时，自动新建一条客户记录。
- **1 条**：保存真实 `record_id`，再读取该记录当前值。
- **2 条及以上**：停止写入，只给出不含联系方式的候选摘要，请用户选择。不能自行挑选，也不能另外新建。

新建记录的最低识别要求：

- 有已确认的客户姓名，或者能稳定区分客户的约定称呼；并且
- 另有至少两项互相印证的信息：完整联系方式、项目地址、到店日期、接待销售或来源渠道。

不满足最低要求时停止新建，告诉用户还缺哪些信息。创建前最后一次查重必须包含现有证据中区分度最高的字段；有完整联系方式时必须查联系方式。

## 判断哪些内容可以写

先读取目标表的真实字段和字段类型。只有当前存在、允许写入的字段才可使用。不要把下面的示例当成固定结构：

- 客户姓名、项目地址、意向产品、审美偏好、决策角色、关注重点；
- 是否到店、到店时间、是否加微信；
- 当前阶段、当前卡点、下一步跟进计划、跟进情况反馈；
- 已经确认且字段类型允许填写的接待销售或搭配师。

以下内容默认不写：

- AI 推测的需求、预算、身份、购买意愿、优先级或客户标签；
- 建议话术、销售评价、评分和培训建议；
- 没有明确说出的成交金额、未成交原因、承诺时间和产品信息；
- 只读字段、公式字段、查找引用字段，以及目标表中不存在的选项。

## 比较新旧值

对每个准备写入的字段分别处理：

- 原值为空，新值有直接证据：可以补充。
- 原值与新值意思相同：不写，记为“无需修改”。
- 原值不为空且与新值不同：不覆盖，记为“待人工确认”。
- 客户在录音中明确否定了旧信息：仍不直接覆盖。列出旧值、新证据时间点和来源，请负责人确认后再改。
- 多选字段只能使用目标字段已经存在的选项；不能为了写入自动增加选项。

“当前阶段”“当前卡点”“下一步跟进计划”等会变化的字段，也不能只凭录音日期较新就覆盖。只有用户在当前任务明确确认替换，或者现有记录能够证明旧值的适用时间已经结束时，才可以修改非空旧值。

同一份录音再次处理时仍按上面的规则比较。相同内容应全部变成“无需修改”，不能再次追加相同文字。

新建记录只填写已有来源直接证明的字段。没有证据的字段留空，不为了让记录看起来完整而猜测。

## 写入步骤

1. 用 `base +url-resolve` 从客户资料表链接取得真实 `base_token`。
2. 用 `base +field-list` 读取目标表字段和类型。
3. 用 `base +record-search` 做精确查询；必要时再用 `base +record-get` 核对唯一候选。
4. 唯一匹配时，形成三份清单：准备写入、无需修改、待人工确认。没有准备写入项时不要发送空更新。
5. 唯一匹配时，写入前再次读取目标记录；当前值如果已经变化，重新比较。使用 `base +record-upsert --record-id <真实记录 ID>` 更新。
6. 0 条匹配时，确认满足最低识别要求，再用最强字段做最后一次查重；仍为 0 条才可使用不带 `--record-id` 的 `base +record-upsert` 创建一条记录。
7. 用写入返回的 `record_id` 执行 `base +record-get`，逐项核对实际写入字段。

飞书命令的参数以执行时的 `lark-base` Skill 和 `--help` 为准。不要根据旧命令或记忆猜参数。

## 结果说明

完成后只需告诉用户：

- 客户称呼、记录 ID，以及本次是更新还是新建；
- 哪些字段已经写入；
- 哪些字段原来就相同；
- 哪些字段因为冲突、证据不足、字段限制或权限问题没有更新；
- 飞书读回是否成功。

不要在结果说明中显示完整联系方式、完整地址或逐字稿正文。
