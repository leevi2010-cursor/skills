# 私享国际销售录音分析

把一份销售录音变成一份有证据、可复核、可执行的销售分析报告。不要建立新的客户事实库，也不要把 AI 判断写成客户事实。

## 运行配置

通过环境变量提供业务入口，不把客户目录、租户标识或本机绝对路径写进公开 Skill：

- `SHOWROOM_PROJECT_ROOT`：项目根目录。
- `SHOWROOM_AUDIENCE_DIMENSIONS`：客群维度文件；可选。
- `SHOWROOM_SALES_REVIEW_ISSUE`：销售复盘事项文件；可选。
- `SHOWROOM_LARK_PARENT_TOKEN`：报告归档的飞书知识库父节点 token。
- `SHOWROOM_LARK_PROFILE`：经过授权的 `lark-cli` profile。
- `SHOWROOM_LARK_BASE_URL`：飞书租户基础地址，例如 `https://example.feishu.cn`。
- `SHOWROOM_PRIVATE_EVIDENCE_ROOT`：原录音和逐字稿的私密工作目录。

执行前检查必需变量，并读取项目根目录最近的 `AGENTS.md`。需要飞书归档时，`SHOWROOM_LARK_PARENT_TOKEN`、`SHOWROOM_LARK_PROFILE` 和 `SHOWROOM_LARK_BASE_URL` 缺一不可；缺失时停止外部写入并告诉用户要补什么。项目规则禁止修改的方法目录继续只读。

## 输入路由

先判断输入属于哪一种，再读取 [输入处理](references/input-routing.md)：

1. **录音逐字稿**：直接使用原文。保留说话人、时间点和来源。
2. **本地录音源文件**：在本机转写，不把原音频上传到第三方。先运行 `scripts/ensure_local_transcription.sh`；再用 `ffmpeg` 检查音频，用 `mlx_whisper` 生成带时间点的 JSON 和文字稿。
3. **飞书妙记链接**：先用 `lark-minutes +detail --transcript` 下载逐字稿，再用 `lark-minutes +download` 下载原录音。分析基于逐字稿，原录音只用于抽查听不清、数字、产品名和关键承诺。

如果输入不是家具展厅销售或客户接待录音，说明判断依据并停止，不套用本 Skill。

## 身份门槛

正式报告前必须确认：

1. 客户姓名或双方约定的称呼。
2. 接待销售姓名。
3. 录音日期和场景。
4. 每位说话人分别是客户、家属、销售还是其他人员。

优先从用户说明、妙记说话人、文档标题和逐字稿自我介绍中识别。不得只凭声音、性别、口音或姓名猜身份。

接待销售不得使用项目默认值，也不得根据历史记录、常见接待人员、声音、说话方式或在场人员自行推定。销售姓名必须由用户明确指定，或由妙记说话人姓名、自我介绍、排班记录、客户记录等可靠来源直接确认，并在报告中写明确认依据。

如果只能判断某位说话人是销售，但不能确认其姓名，必须先询问用户。用户明确给出姓名后才能继续正式分析。销售姓名未确认时，不得生成销售评价、评分、个人建议、建议话术或正式飞书报告。

任一身份仍不清楚时，先向用户列出缺失项并停止。不得生成销售评价、评分、个人建议或建议话术。

## 分析规则

读取 [报告格式](references/report-format.md)，然后：

1. 使用客群维度表中的编号、名称、选项和未确认状态。主要维度逐项检查，但不为了填满表格而追问无关信息。
2. 分开写客户原话、已确认事实、员工判断、AI 判断和未确认信息。
3. 按五个环节分析：建立信任、了解需求、制定方案、解除疑虑、锁单成交。
4. 每个环节写证据时间点、完成情况、建议、建议话术和下一步。
5. “下一步”不是第六个环节。每个环节都要说明谁、何时、做什么、怎样确认完成。
6. 客户可能返回前一个环节。记录返回原因，不强行写成直线流程。
7. 没有进入的环节写“本次未进入”。证据不足写“待确认”，不得补猜。
8. 建议话术使用高中毕业生能听懂的短句，不使用职场黑话，不用话术施压客户。
9. 第一版不做情绪识别和自动绩效评分。评分规则未经业务确认时不得给数字分。

## 飞书归档

用户提交输入并要求分析，即授权把完成后的正式报告写入已配置的父目录。写入前仍需验证 profile、身份、父节点标题和 space_id；不符合时停止，不能切换租户或身份。

标题格式固定为：

`【销售复盘】YYYYMMDD｜客户称呼｜销售姓名｜场景`

规则：

- 一份录音一个子文档。
- 同一录音以妙记 token；或文件 SHA-256；或“日期 + 时长 + 客户 + 销售”作为稳定标识。
- 创建前列出父节点子文档并检查稳定标识和标题。已存在时更新原文档，不重复创建。
- 使用 `docs +create --parent-token "$SHOWROOM_LARK_PARENT_TOKEN"` 创建子文档，正文默认使用 XML。
- 正文只放报告、来源链接或来源标识。客户联系方式、完整逐字稿和本地路径不放入正文。
- 创建或更新后必须 `docs +fetch` 读回，检查标题、客户、销售、五个环节和来源标识。
- 成功后返回飞书链接；读回失败不能报告完成。

所有飞书命令显式使用：

```bash
env -u HERMES_HOME lark-cli <service> <command> \
  --profile "$SHOWROOM_LARK_PROFILE" --as bot
```

飞书具体参数以执行时读取的 `lark-minutes`、`lark-doc`、`lark-wiki` Skill 和命令帮助为准，不凭记忆拼参数。

## 失败处理

- 音质差、多人重叠、转写失败：指出具体区段和原因，不生成看似完整的报告。
- 妙记无权限：报告权限问题；未经用户明确要求，不自动申请权限。
- 依赖安装失败：保留原文件，报告缺少的工具和最小补救动作，不改系统配置。
- 飞书写入失败：保留本地私密报告，不改投其他租户，也不把本地文件假装成飞书交付。

## 完成标准

- 身份已经确认。
- 主要客户维度已逐项检查。
- 五个销售环节都有证据状态。
- 所有建议能回到逐字稿时间点。
- 每个实际下一步都有负责人、时间和完成标准。
- 飞书子文档写入并读回成功。
- 原录音、完整逐字稿和客户联系方式没有进入普通 Git 仓库。
