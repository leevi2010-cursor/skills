## 结构定义

把用户的核心问题作为第 0 层根节点。每个第 0–4 层节点必须恰好产生 3 个子节点，第 5 层停止。

| 层级 | 节点数 | 作用 |
| --- | ---: | --- |
| 0 | 1 | 用户的核心问题 |
| 1 | 3 | 三个直接回答 |
| 2 | 9 | 每个直接回答的三个主要分支 |
| 3 | 27 | 机制、组成、策略或条件 |
| 4 | 81 | 细节、证据、约束、步骤或指标 |
| 5 | 243 | 原子解释、原子行动、观察信号或验证方法 |

总节点数必须为 364。三叉是探索约束，不代表世界天然只有三个答案，也不代表三项必然穷尽所有可能。

## 三种问题模式

### 是什么 `what`

让子节点回答“父节点由什么构成、属于什么、表现为什么、边界在哪里”。优先使用以下关系：

- 整体 → 组成部分
- 概念 → 类型或维度
- 抽象定义 → 可观察特征
- 系统 → 输入、过程、输出
- 对象 → 核心、边界、变体

不要把“为什么产生它”冒充“它是什么”。如果概念本身包含形成过程，可把过程作为组成维度，但要保持关系明确。

### 为什么 `why`

让每个子节点对父节点构成真实的因果解释。优先从下列三分框架中选择最适合父节点的一组：

- 直接原因、使能条件、维持机制
- 个体内部、外部环境、互动反馈
- 生物基础、心理机制、社会结构
- 信息不足、激励偏差、执行约束
- 历史形成、当前触发、循环强化

不要混淆原因、症状、结果和同义改写。用“如果去掉该子节点，父节点发生概率是否会改变”检查因果贡献。

### 怎么办 `how`

让每个子节点成为可执行的解决方向。优先从下列三分框架中选择最适合父节点的一组：

- 预防、发现、纠正
- 降低成本、建立缓冲、转移风险
- 人员、流程、工具
- 立即行动、短期建设、长期机制
- 获取信息、形成判断、采取行动
- 减少问题、增强能力、改变环境

下层必须逐步出现行动主体、资源上限、判断信号、停止条件或验证方法。不要只写“加强、重视、优化、提升”等空泛动词。

### 综合 `mixed`

用户明确要求同时分析“是什么、为什么、怎么办”时，让第 1 层恰好对应这三项。进入每个分支后分别沿 `what`、`why`、`how` 的语义递归。不要在同一兄弟组中随意混合定义、原因和行动。

## 三分方法

为每个父节点选择一个连贯的三分维度，不要机械套用固定模板。三项应满足：

1. **关系一致**：三项都以同一种逻辑回答父节点。
2. **彼此区分**：任意两项不能只是措辞不同。
3. **覆盖主要空间**：优先选影响最大、解释力最强或最可行动的三项。

可用但不必强求严格 MECE。现实中分支可能相互作用；需要时在标签中说明“相互强化”或“共同作用”。

选取三项时依次检查：

1. 这三项是否处于同一抽象层？
2. 每项能否独立继续拆出三项？
3. 删除其中一项后，是否丢失一个重要视角？

## 五层递归语义

### 第 1 层：直接回答

给出用户最需要看到的三个主方向。避免从背景知识开始，直接回答问题。

### 第 2 层：主要子问题

把每个主方向拆成三个可独立思考的部分。此层决定全树的逻辑骨架。

### 第 3 层：机制或策略

进一步解释“如何发生、由何构成、通过什么实施”。开始连接现实场景。

### 第 4 层：条件、证据与约束

加入会改变结论的条件、可观察证据、资源限制、风险边界、实施步骤或中间指标。

### 第 5 层：原子节点

停止在能被理解、观察、验证或执行的最小单位。一个好的叶节点通常能转成：

- 一个可以核对的事实；
- 一个明确标注的假设；
- 一个可以执行的动作；
- 一个判断继续或停止的信号；
- 一个能够推翻上层结论的反例。

## 分支质量检查

逐组检查所有兄弟节点：

- 是否直接回答父节点？
- 是否只是重复父节点？
- 是否存在同义项？
- 是否混入不同抽象层级？
- 是否为了凑三项而加入低价值内容？
- 是否能自然继续拆解？

发现问题时优先重选三分维度，不要只修改措辞。

避免反复使用完全相同的底层模板。不同表层问题可以汇合到共同机制，但应说明共同机制如何在当前路径中起作用。

## 证据与不确定性

递归不能只扩大作者原有认知。越深入越要引入三类校正：

1. 外部证据：资料、数据、案例、标准或用户行为；
2. 反例检查：什么情况会使当前分支不成立；
3. 行动验证：用什么最小实验获得新信息。

对无法确认的内容使用“可能”“假设”“需验证”等标记。对价值判断说明它取决于什么偏好。对高风险建议给出边界、停止条件或需要人工确认的位置。

## 通俗表达与节点内容

每个节点都必须包含三个字段：

- `label`：8–24 个汉字为宜，用一句容易扫读的短句表达核心意思。
- `detail`：用 1–3 个短句展开说明，解释该节点与父节点的关系，并给出一个可观察信号。不能只是换词重复标题。
- `example`：写一个多数高中毕业生能理解且容易共鸣的具体场景。例子中要能看见人物、行动和结果。

默认使用高中毕业生能一次读懂的语言：

- 优先使用日常词，不用术语显示专业感。
- 必须使用术语时，在同一句中解释其含义。
- 一句话只表达一个主要意思，少用多层从句。
- 把“系统性、元认知、目标函数、路径依赖”等抽象词改写成可观察行为或普通语言。
- 例子优先来自学习、工作、家庭、消费、人际关系和日常选择；避免连续使用同一个例子。

## 节点编号规则

- 编号由渲染器按路径自动生成，不由内容作者手写。
- 根节点编号为 `0`。
- 第一层编号为 `1`、`2`、`3`。
- 更深层在父编号后追加兄弟序号，例如 `2.1`、`2.1.3`、`2.1.3.2.1`。
- 同一份 HTML 内所有 364 个编号必须唯一。
- 聚焦卡片、子节点按钮和面包屑都必须显示编号。
- 提供“复制节点引用”按钮，复制格式为“节点 2.1.3：节点标题”，方便用户继续与 AI 沟通。

## HTML 交互要求

- 首屏显示根问题及三个第 1 层答案。
- 每次聚焦一个节点并显示其三个子节点，避免同时摊开 364 个节点。
- 显示当前层级、总节点数和路径面包屑。
- 聚焦节点同时显示编号、标题、详细解释和通用例子。
- 子节点按钮显示子节点编号和短标题。
- 支持返回上一层、返回根问题和点击路径跳转。
- 支持一键复制当前节点的“编号 + 标题”。
- 第 5 层明确提示递归结束。
- 使用原生按钮和键盘可访问交互。
- 在 736px 和 320px 宽度下均不重叠或裁切。
- 所有颜色使用主题变量；不加载外部资源；不发起网络请求。

## HTML 交付要求

- 每次都同时尝试内联显示交互图，并提供可点击的独立 `.html` 文件链接。
- 两种交付必须来自同一个已经验证的 HTML 文件，不能分别生成内容可能不同的版本。
- 不得把文件链接设为“仅在用户主动要求下载时提供”的可选项。
- 不得只输出本地路径；必须使用当前产品支持的附件或文件链接。在 ChatGPT Work mode 中使用绝对 `sandbox:` Markdown 链接。
- 在链接下明确说明：如果内联交互图未显示，可使用独立 HTML 链接。
