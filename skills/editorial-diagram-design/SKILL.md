# 编辑式关系图

先确定首屏要回答的一个问题，再选图型。图不是目录：若上下层只是同一目录收录，用列表；读者需要判断支撑、约束和依赖时，才画关系图。只有真实父子关系才用树；流程或状态演变另画，不在关系图里硬拼。

## 步骤

1. **核事实，再排构图。** 先列节点、连线方向、关系词、依据和确认状态。关系未核实就标「待确认」；只知道两个目标存在，不能因此补一条线。单纯没有数据不等于缺少目标。无依据的节点可独立显示。
2. **只让一个主要结果成为焦点。** 用正交走线和分开的连接端口；标签靠近对应线，避免压节点、跨线或靠颜色解读。长标签优先自然换行，而不是缩小字号。品牌强调色给少数关键信息，不用阴影、网格和重复色块制造层级。
3. **为状态保留不同的视觉语义。** 确认关系用实线；建议关系用虚线并标明状态；候选目标用带「候选／未采纳」文字的虚线边框。图例说明线与框分别代表什么。候选只能开草稿或预览；不能因为点了一下就改正式记录或创建项目。
4. **按阅读顺序逐级进入。** 总览不默认展开某个目标的计划、任务和指标。点正式节点进入下一层，保留返回或面包屑。若加入交互，用键盘可达的控件和清楚的焦点样式；SVG 可配可访问的文本说明与真实按钮。
5. **桌面、手机分别排图。** 宽屏可横排；窄屏可换成竖向版或等义的分层阅读顺序，保留关系方向和状态。不把整张桌面图等比缩成小字，也不强迫横向拖动来读核心信息。

## 交付验收

- 优先生成可离线打开的自包含 HTML，图用内联 SVG 且不依赖 CDN；需要审阅时另截有代表性的桌面、手机图。
- 在可用浏览器实际打开并检查代表性尺寸（如 1440、1024、768、390），长标签不截断，走线与标签不重叠，无横向溢出；用键盘检查下钻、返回、候选预览、关闭与回焦。没做的检查不报通过。
- 保留已知的项目视觉规范与可核实的业务关系。预览要明确不写回；发布与真实数据写入另外确认范围。

## 方法来源

参考 Cathryn Lavery 的 [Diagram Design v2.6](https://github.com/cathrynlavery/diagram-design)（上游为 MIT），尤以其样式指南和架构构图原则为参考。本 Skill 是项目实践的中文适配，不包含上游脚本、模板代码或品牌素材，不需要安装上游工具。
