# 家具展厅咨询视频脚本

把一个已经由人审核通过的家具展厅选题写成可检查、可拍摄的脚本候选。默认主要目标事件是“咨询”。本 Skill 只负责脚本编写和制作难度检查，不代替选题审核、拍摄授权、账号发布、广告投放或效果验证。

## 先检查能否进入脚本

只有同时取得以下信息时才开始写完整脚本：

- 选题已经由人明确审核通过；
- 审核人或用户能够被识别；
- 审核对象是一个具体选题，而不是宽泛方向；
- 用户没有要求在同一轮中跳过人工审核，直接从平台信号批量生成脚本。

缺少人工审核时停止写脚本，只返回：

```text
状态：未进入脚本
原因：选题尚未经过人工审核
需要补充：候选选题、审核人和“通过／补证据后再审／放弃”结论
```

如果用户同时要求选题研究和写脚本，先完成候选选题，等待人明确选择通过项，再在后续消息中写脚本。不要用模型自己的判断替代人工审核。

## 必读材料

开始起草前完整读取：

1. [脚本工作单](references/script-work-order.md)：输入字段、输出结构和状态写法。
2. [低搬动镜头方法](references/low-move-shot-methods.md)：制作等级、重家具判断和替代画面。

用户或项目另有权威工作单时，先读该工作单。若它与本 Skill 冲突，保留冲突并请用户决定，不要静默选择。

## 收集输入

先从已审核选题和现有资料中提取，不为了填表追问无关信息：

- 选题编号、题目、审核人、审核日期和审核意见；
- 平台需求信号及证据边界；
- 目标客户所处阶段、具体场景、一个核心问题和期待结果；
- 用户可感知的代价；
- 一个专业判断；
- 一个可观察的证明方法；
- 客户到店后能实际比较或确认的事情；
- 一个咨询动作、真实承接入口和承接人；
- 可用产品、实测尺寸、材质、空间、人物和历史素材；
- 素材的拍摄权、肖像权、音乐字体及广告使用权状态；
- 可用人员、设备、拍摄时间、展厅营业影响和家具搬动限制。

除了“人工审核已通过”以外，其他信息缺失时可以形成脚本候选，但必须写成“待确认”，并删除依赖该信息才能成立的口播或数字。不要补猜产品型号、尺寸、服务内容、价格、免费承诺或客户案例。

## 确定一个说服命题

每条脚本只保留：

- 一个具体场景冲突；
- 一个会改变客户选择的专业判断；
- 一个主要画面证明；
- 一个到店后才能更好完成的比较或确认；
- 一个咨询动作。

共同品牌观点可以出现，但不能替代具体问题。不要把多个专业判断或多个行动要求塞进同一条视频。

## 先判断制作难度，再排镜头

家具如果需要两人以上、搬运工具、地面保护，或会明显打断展厅营业，就按重家具处理。逐镜安排前先给每个证明动作标记制作等级：

- `L0`：家具位置不变；只移动人物、镜头或测量工具。
- `L1`：一人可安全移动的小件、样板或饰品；不伤地面，不影响营业。
- `L2`：需要多人、工具或短时封场的同区域调整。
- `L3`：整件沙发、餐桌、柜体等跨区域替换，或需要重做整组陈列。

默认选择 `L0` 或 `L1`。出现 `L2` 或 `L3` 时，必须同时给出一个 `L0/L1` 替代方案，并解释为什么原方案仍值得保留。不得为了做一个固定机位的替换镜头，临时反复搬动重家具。

优先使用这些证据：

- 真人坐、起身、转身、通行、取物和清洁，让使用问题可见；
- 实测尺寸、激光测距、可移除地贴或俯视平面图，让比例和通道可见；
- 在固定家具旁比较材质样板、色卡或小件，让色彩和材质关系可见；
- 拍摄展厅里已经存在的不同组合，并明确写“不同展区示例”，不冒充同场景前后对比；
- 使用按真实尺寸制作的轮廓、俯视图或增强现实画面，并标明“尺寸模拟”；
- 利用正常换场、到货或陈列调整时一次拍完重家具变化，不专门为视频重复搬运；
- 使用已经取得广告权利的历史拍摄，标明来源和拍摄条件。

推镜、拉镜、遮挡转场、暗场亮灯、细节特写和人物进入画面可以增加观看变化，但不能单独证明比例、颜色或使用效果。镜位、焦段或灯光不同的画面不得冒充受控的前后对比。

## 编写逐镜脚本

使用 [脚本工作单](references/script-work-order.md) 的完整结构。基准版可先按 35–50 秒安排，内容更短时直接做 15–25 秒版本，不为接近 45 秒增加走路、坐下或空镜。

逐镜安排遵循：

1. 首镜或首句在 3 秒内给出具体处境、代价或反常识画面。
2. 随后的镜头依次完成场景识别、专业判断、可视化证明、到店价值和单一行动指令。
3. 每个镜头必须增加一项新信息，或证明前一句判断。
4. 口播只说画面能支持的内容。画面只是示意时，屏幕文字必须标明“示意”“尺寸模拟”或“不同展区示例”。
5. 对每个镜头写明实现方式、制作等级和低成本替代方案。
6. 产品库可用时写真实产品编号和实测信息；不可用时写所需素材条件，不编造产品。
7. 一条脚本只测试一个主要变量，例如首镜、专业判断表达或证明方式。不要同时改时长、客群、口播和行动指令后再比较结果。

## 真实与权利边界

- 展厅陈列不得写成客户真实住宅或真实交付案例。
- 不同展区画面不得写成同一空间的严格前后对比。
- 模拟轮廓和增强现实画面不得写成实拍结果。
- 未核实的尺寸、价格、材质、服务、时限和效果不得进入口播。
- 未确认免费、上门、设计深度或交付范围时，不做相关承诺。
- 第三方图片、音乐、字体、人物和历史视频没有广告使用权时，不安排进正式素材。
- 不按地域、职业、年龄或性别猜测生活需求；只使用选题证据中真实出现的空间、行为和问题。

## 验证输出

把脚本候选保存为 Markdown，然后运行：

```bash
python3 <this-skill-directory>/scripts/validate_script.py <draft-script.md>
```

验证失败时先修正，不交付看似完成的脚本。若当前环境不能运行脚本，按同一检查项人工复核，并明确说明未完成机器检查。

机器检查只验证结构、状态、逐镜表、制作等级、单一行动指令和部分禁用承诺。它不能证明平台会有流量、客户会咨询、画面安全或素材已有广告使用权。

## 禁止写法

- “保证不会买错”“一定有效”“百分之百转化”等结果承诺；
- 把 45 秒写成平台统一最佳时长；
- 让客户同时私信、评论、关注、预约、到店或扫码；
- 用慢走、坐下、扫过陈列等无信息镜头凑时长；
- 把改变焦段、镜位、曝光或灯光后的画面写成同条件对比；
- 默认安排反复搬动重家具，却不写人员、设备、安全条件和替代方案；
- 把脚本候选写成已验证的获客方法。

## 完成标准

- 选题的人工作出“通过”结论并被记录；
- 只有一个核心问题、一个专业判断、一个主要证明和一个行动指令；
- 每个镜头都有证明任务或新增信息；
- 每个镜头都有制作等级；
- 所有 `L2/L3` 镜头都有 `L0/L1` 替代方案；
- 重家具不作为日常脚本的默认变化对象；
- 缺失信息、权利状态、拍摄授权、发布授权和广告投放授权分别写清；
- 输出明确标为“脚本候选”，不声称已验证获客效果；
- 验证脚本通过。
