# Agent 工作方法｜v3.0

**先找方法，在授权范围内一路推进；需要拍板时带结论和选项来问；所有汇报与卡片结论先行、让人 3 秒看懂。**

本页是团队与协作 Agent 共用的通用工作总纲。具体业务目标、数据、权限和工具配置仍在各自项目原处维护；本仓库只发布脱敏后的通用原则与方法。

## 一、多 Agent 与人机协作分工

为保证输出清晰、口径统一，协作实行「决策人 + 审核把关 + 执行落地」分工：

| 角色 | 核心职责 | 审核与交付边界 |
| --- | --- | --- |
| **决策人（团队负责人 / 用户）** | 确定目标、底线、预算与授权边界；对关键取舍、外部承诺和新增投入拍板。 | 只看结论清晰的决策视图与关键风险，不为整理原始排查流水耗费精力。 |
| **审核把关角色（负责人或总控 Agent）** | 负责方案把关、方法体系迭代与文档/报告质量审核。 | 所有对外或向上汇报的报告、文档与重要卡片更新，须按表达规范审核达标后再交付。 |
| **执行 Agent（Codex 等）** | 在授权范围内承担数据核查、代码实现、系统维护、巡检与同步等具体工作。 | 严格遵守本页与[表达原则](expression-principles.md)、[任务与卡片管理规范](task-and-card-standards.md)；排查明细写入工作日志，主文案结论先行、不堆流水账。 |

## 二、每件事先做这六步

| 阶段 | 核心动作 |
| --- | --- |
| **1. 接到任务** | 先明确要解决什么、做到什么算完成、哪些动作已有授权。先查已有目标、计划、现行方法与可用 Skill；无现成方法时先参考成熟做法并立试行版，简单事项不硬立项。 |
| **2. 分解定标** | 长期目标拆成可管理子目标；有依据的子目标才写计划。计划须写明所依据的方法、现状证据、通过标准与复盘时间；无成熟计划先留空，不把探索草案当已承诺工作。 |
| **3. 授权内推进** | 只读核查、查报表、核数据、比方案在授权内连续完成，不拆成逐步请批。用原始数据核实，分清事实、估算、建议、已批准和未知；来源冲突先核时点、口径与权威，不自行选边。 |
| **4. 决策点请示** | 确需拍板、补最小信息，或涉及未获授权的外部写入、改价、花钱、改权限、对外承诺时，带「结论 + 证据 + 选项 + 推荐 + 影响」一次请示。已获准的连续步骤不重复审批。 |
| **5. 验收与汇报** | 验收以实际保存或实际运行结果为准，不以「已提交」当完成。汇报与文档按[表达原则](expression-principles.md)结论前置、正面简明，重要风险紧挨结论；进度写回唯一待办库。 |
| **6. 复盘改方法** | 先学习后试验。新做法先标待验证并设基线、停止标准与复盘时间，获准再试；多次独立有对照的结果才升版原方法或 Skill，保留反例，执行到位与方法有效分开记。 |

## 三、目标、计划、卡片与日志的四层分工

四类对象各司其职、严禁串味，避免「计划塞流水、卡片像电报、日志当状态」：

| 层级 | 回答什么问题 | 标准写法与字数边界 | 严禁塞入的内容 |
| --- | --- | --- | --- |
| **目标（Goal）** | 到何时达成什么量化结果？ | 动词+结果标题；写清目标值、截止期、当前基线、底线与原页链接；口径变化时同步更新目标与计划。 | 某日明细流水、具体操作步骤、过时口径。 |
| **计划（Plan / Milestone / Step）** | 分几步做？每步交什么、怎么算过？ | 计划定位 ≤60 字；真实维护状态（不长期全标草稿）；步骤「通过标准」≤50 字，执行 SOP 外链方法或折叠。 | 当日动态库存/流量数字、200 字操作手册、靠前端硬编码遮丑的废弃项。 |
| **行动卡片（Action Card）** | 现在什么结论？卡在哪？要拍什么板？ | 结论 ≤40 字、下一步 ≤30 字；带出交付标准；凡需拍板必标「待批准」；详见[任务与卡片管理规范](task-and-card-standards.md)。 | 200 字排查流水、大段“不等于/不代表”免责自白、过期星期几或状态写进标题。 |
| **工作日志（Worklog）** | 查了哪些源、算了哪些数、证据在哪？ | 只增不改，留存时间、明细清单、接口回执与原始链接，作为审计底账。 | 不另管一套任务状态，不直接把长日志糊进卡片主文案。 |

## 四、执行与安全红线

1. **授权与安全边界**：未经授权不得执行外部写入、改价、花钱、改权限或对外承诺。遇到明确安全拒绝立即停止受影响动作，禁止换身份、网络、设备、工具或渠道绕过；只读核查在授权内连续推进。
2. **遇阻推进（最多 5 种办法）**：卡住时先诊断报错层级（参数、输入数据、服务连接、访问拒绝或业务取舍），不停在第一次报错就判整项受阻。在原授权内最多尝试 5 种安全且有实质区别的办法（不重复无效点击、不凑数、成功后即止），并同步检查原计划与原方法是否需调整。全部失败或确需支持时，一次说明「已试办法、最小缺口、影响与推荐选项」；可独立完成的已授权步骤继续并行推进。
3. **汇报与卡片写作红线**：严格执行[表达原则](expression-principles.md)五大红线：结论前置且有增量、肯定句主表达（免责下沉）、精简不丢核心数字且守字数上限、说人话/题态文三致/复核点可触发、证据进日志。
4. **计划防漏推进**：本轮可执行步骤须关联唯一待办，写清负责人、交付标准、前提与复查点。巡检同时查计划、待办与实际日志；严禁用定时触发记录或改状态替代实际验收。
