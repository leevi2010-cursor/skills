# 任务与卡片管理规范｜v2.0

本规范统一团队与 Agent 的**目标、计划、行动任务卡片与工作日志**写作标准、状态流转与维护纪律。任务只在唯一权威位置维护，卡片只服务 3 秒决策，过程明细全部沉淀到工作日志。

## 一、四层对象的写入边界（严禁串味）

| 层级 | 必须写清楚什么 | 严禁写法 |
| --- | --- | --- |
| **目标（Goal）** | 动词+结果标题；量化目标值与截止期；当前已核基线；约束底线与原页链接。口径调整时同步改目标与计划。 | 留空描述、标题只有名词、目标口径与现行计划打架。 |
| **计划与里程碑（Plan / Milestone）** | 计划定位（purpose）≤60 字，只写稳定范围与目标；真实维护状态（进行中/试点中/待批准/已暂停/已完成）；里程碑写明交付物、1–2 条通过条件与目标日期。 | 把某天具体库存/流量数字写进计划定位；进行中计划长期全标草案；废弃里程碑靠前端隐藏而不归档。 |
| **计划步骤（Step）** | 拆为两层：主视图只留**「交付物与通过标准」（≤50 字，可判是/否）**；详细执行口径与 SOP 外链方法文档或收进折叠说明。 | 把 200 字操作手册和防呆禁令全揉进验收字段。 |
| **行动卡片与日志（Card / Worklog）** | 卡片只呈现当前决策状态；每次核查的数据来源、明细清单、接口回执与免责口径全部写入工作日志。 | 在卡片主文案堆 200 字排查流水，或在日志里另管一套任务状态。 |

## 二、行动任务卡片 5 栏标准模板

所有个人待办与 Agent 任务卡统一按以下 5 栏结构维护，确保读者扫一眼就能看清结论并识别待拍板项：

| 卡片栏位 | 写作标准与字数红线 |
| --- | --- |
| **标题** | 统一格式：**`[模块/项目] 动词 + 具体对象`**（如 `[库存] 监控四仓断货与补货预警`）。禁止把“周一”“暂缓”等时间或状态写进标题。 |
| **状态 + 负责人 + 复核点** | 单值状态（按第三节严格判定）+ 唯一负责人 + 可触发的具体复核日期/时间或触发后时限。 |
| **当前结论（≤40 字）** | 首句给结论，用肯定句写清全盘结果、核心数字或卡住的下游事项；禁止堆砌排查步骤和否定式免责。 |
| **交付与验收标准（≤50 字）** | 直接带出关联步骤的通过条件（1 句话），卡片上无需跳转即可看懂交什么算完成。 |
| **需拍板 / 当前卡点** | 仅「待批准」「受阻」高亮显示：待批准写清「请批什么 + A/B 选项与推荐理由」；受阻写清「缺什么 + 谁来解除 + 复查时间」。 |
| **下一步（≤30 字）+ 折叠证据** | 下一步只写「谁在何时做什么」；详细数据、口径限制与来源链接统一收进折叠区或工作日志。 |

## 三、状态定义与去重纪律

| 状态 | 进入条件 | 严禁误标 |
| --- | --- | --- |
| **待批准** | 已具备判断依据，唯一卡点是等待负责人审批、拍板或做业务选择（卡片应置顶提醒）。 | 严禁把需拍板的事项标成「受阻」导致审批项被淹没；审批落地后立即改状态。 |
| **受阻** | 外部依赖、权限或条件确实阻断推进，且已诊断并尝试授权内替代办法仍未解除。 | 不停在第一次报错就标受阻；未试过的办法不写成已失败；必须写清谁负责解除阻塞。 |
| **进行中** | 已有实际执行动作证据且仍在持续推进。 | 禁止状态标「进行中」但进度写「未开始」，或仅凭旧会话时间冒充进展。 |
| **待核实** | 等待外部回复、平台出数或尚未收到真实执行回执。 | 不把“未出数”当“无新增”或“已失败”。 |
| **待承接** | 已立项排入队列，尚未启动执行。 | 不把过期未动的老待办长期堆在活跃列表，定期清理或重排。 |
| **已暂停 / 已完成** | 已暂停须记录暂停决定与恢复条件；已完成须具备验收证据与回执链接。 | 不因整理列表自动重启暂停/取消项；不以“发过文档”代替验收完成。 |

**去重与唯一写入**：同一事项在全库只保留 1 条活跃卡片（不区分个人表与 Agent 表重复建卡），历史合并或替代记录在数据库归档保留追溯。

## 四、待办与工作日志分离

- **行动任务卡片**：维护唯一当前状态、结论、负责人、复核点与下一步。
- **工作日志**：按日期降序（最新日期在前）记录当天发生的事实、明细数据、接口回执与原始证据；涉及任务时只引用任务编号，不另管一套状态。
