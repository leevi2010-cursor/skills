# 表达原则｜v1.2

从读者需要出发，只说对方需要知道的，让对方少费力。

### 先选对内容，再把话说清楚

| 要注意什么 | 怎样做 |
| --- | --- |
| 只写对读者有用的内容 | 先想对方关心什么、要判断什么、接下来要做什么。正文先讲结论，删掉对方不需要的写作依据、自我说明和过程说明。 |
| 讨论过程与结论分开 | 讨论过程不直接搬进正文。确有必要保留的推导和参考证据，放在文末附录，供需要的人查看。附录不是必需，不放全部讨论流水；已有原始资料就链接原处，不另抄一份长期维护。 |
| 让读者少费力 | 用常见词，按容易理解的顺序说。抽象词说不清，就拆开说明，必要时举具体例子。 |
| 重要信息不能为了短而删 | 会影响判断的来源、假设、限制、风险和下一步要说明。影响理解结论的重要条件和风险，留在结论旁边，不能藏到附录。用户明确问方法或过程时，直接回答相关内容。 |

### 让没学过相关专业课的人也能看懂

写给没学过这个领域专业课的大学二年级学生。让读者知道在说什么、为什么重要、接下来谁做什么，以及怎样判断结果。

| 怎样写 | 具体做法 |
| --- | --- |
| 用常见的词，句子短一点 | 尽量说具体的人、事情、条件和结果。一句话太长，就拆成几句。 |
| 说不清楚，就继续拆开 | 不用一个抽象词盖住问题。补充说明或例子，直到读者能理解它指什么。 |
| 必要的专业词先解释 | 先用日常话说明意思，再给出名字。不能只换成另一个同样难懂的词。 |
| 说明现在知道多少 | 已确认的事实、估算、猜想分别说明。缺什么信息、什么还没决定，都具体写出来。 |
| 简单，但不丢意思 | 保留会改变决定的条件、例外、风险和需要谁同意。不能为了短而把话说错，也不能在改写时增加要求。 |
| 能用图表说明，就优先用图表 | 比较几件事用表格，说明先后关系可用流程图。表头和图里的词也要直白；图表不能代替必要解释。 |

### “还没想清楚”也要说清是哪件事

| 实际情况 | 怎样说 |
| --- | --- |
| 还没想清楚希望什么，或不能接受什么 | “还没想清楚最多能承受多大损失，需要先把这个要求说清楚。” |
| 要求清楚，但缺事实信息 | “还不知道这个办法会花多少钱，需要先查费用。” |
| 信息已有，需要用户作选择 | “两个办法的费用已查到，还等你决定选哪个。” |
| 已知会碰到不能接受的情况 | “这个办法超过已确定的费用上限，不能按现在的方案做。” |

### 写完再看一遍

读者能否直接看出谁做什么、什么时候做、怎样判断？如果还要猜一个词的意思，就换成具体说明。简化表达不改变已确认的目标、做事要求和授权。
