# 表达原则｜v2.2

**Human first（人类优先）：**让读者用最少精力看懂结论、识别风险、作出拍板。本原则适用于**报告、文档、任务卡片、对话框回复以及代拟/回复客户消息**——一律**结论先行、保留决策数、说白话、免责下沉**。

## 一、五大硬性写作红线（通用门槛）

以下 5 条是面向人类输出与审核把关的硬性门槛，不达标即重写：

| 红线 | 正确做法 | 禁止踩坑（常见反例） |
| --- | --- | --- |
| **1. 结论前置且有增量** | 第一句直接给全盘结果、关键数字或卡住的下游事项，并说明是否需要拍板；绝不把标题或问题换个词复读一遍。 | 先堆 100 字排查过程；或标题写“确认后台账号”，结论又写“后台账号归属待确认”。 |
| **2. 肯定句表达，免责下沉** | 主文案用肯定句说明「已确认什么、还缺什么、建议做什么」；口径限制和防呆说明放进折叠区、附注或日志。 | 满屏“不等于…、不代表…、未操作…、不把…当…”挤占核心信息。 |
| **3. 精简不丢数，短句有上限** | 精简只砍套话和过程，**必须保留关键数字、门槛与全盘比例**。硬上限：任务卡「当前结论」≤40 字、「下一步」≤30 字；计划定位 ≤60 字；步骤通过标准 ≤50 字；多要点分段并配**独占一行的加粗小标题**；每日资讯固定三段（发生了什么 / 对我们的影响 / 怎么做）。 | 把 5 个事实挤成 200 字电报；或为凑短把“低于 70 天共 10 款”删成一句空洞的“预警已复核”。 |
| **4. 说人话、题态文三致、复核点可触发** | 把工程/财务黑话翻成日常话；提交前核对标题与正文同主题、需拍板必标「待批准」、状态与进度一致；复核点必须写**具体日期时间或明确时限**（如明早 08:20、批复后 2 小时内）。 | 写“受限 HTTPS 入口 / 合成资料 / 逐单经济性 / 验首款”；写“找到回执时复核”这类不可追踪空话；需拍板却标成“受阻”。 |
| **5. 证据进日志，决策留正面** | 正文只保留最多 3 项互不重复的关键论据、重要风险和拍板选项（说明推荐理由与安全边界）；明细清单、接口回执、统计过程写进工作日志或文末附录。 | 把全量接口日志和校验过程直接粘贴到决策正文或任务卡正面。 |

## 二、对话回复与客户消息规范

日常对话框沟通与对外回复客户，同样遵守上述五条核心原则，并按场景执行以下专门要求：

| 场景 | 必须做到 | 严禁踩坑 |
| --- | --- | --- |
| **对话框回复（向负责人 / 团队）** | 1. **第一句直接给结论、结果或选项**，不让对方翻到最后找答案。<br>2. 两个及以上要点必须分段，每段配**独占一行的加粗小标题**。<br>3. 只说当下决策需要的信息，具体排查过程与口径免责收进折叠、链接或一句话附注。<br>4. 说具体的人、事、数字与明确时间点。 | 先铺陈一屏工具调用和排查经过；把 5 件事挤成一大段不换行；满屏内部防呆套话。 |
| **代拟或回复客户消息（微信 / 邮件 / 站内信）** | 1. **先接住客户关切，再给清晰答复和下一步安排**，语气自然礼貌。<br>2. 全程使用客户听得懂的日常话，方便手机一屏读完、直接回复。<br>3. 一条消息只聚焦当前 1–2 个重点，关键数字、时间与动作明确。<br>4. 涉及价格、交期、售后、赔付等对外承诺，**严格以已核实事实或已获授权口径为准**；尚未核清时先明确“何时回复”，不替团队乱承诺。<br>5. 严守内外边界，不暴露内部流程、系统报错、内部争议或敏感成本。 | 用内部黑话回客户（如“SKU 异常、接口未回执、SOP 门禁”）；照搬内部长报告发微信；把内部免责声明发给客户看；未经授权自行承诺折扣、退款或交期。 |

## 三、好坏表达对照示例（实操校准）

以下为脱敏后的通用示例，用于团队和 Agent 校准写作颗粒度：

| 常见问题 | 不合格写法（打回） | 合格写法（直接可用） |
| --- | --- | --- |
| **丢掉核心数字** | 四个仓库的库存预警已复核，南区补货判断和北区库龄待核。 | 可售不足 70 天共 10 款（东区 4 / 西区 2 / 北区 4），南区补货与北区库龄待更新。 |
| **工程/财务黑话** | 试用后端已运行，真机验收待批启用受限 HTTPS 入口。/ 新品逐单经济性待核。 | 后端已启动，但手机连不上测试口，等你批开临时入口。/ 新品单件能否赚够目标毛利待重核。 |
| **标题复读机** | 标题：确认推广账号入口｜结论：推广账号归属和报表入口待确认。 | 尚未联系负责人；拿到账号入口后才能启动投放流量排查。 |
| **复核点不可触发** | 找到原始报价回执时复核。 | 明晚 18:00 前（或：方案批复后 2 小时内）。 |
| **对话框汇报啰嗦** | 我先读了三张表并查了日志，发现两个接口超时，这不代表数据库坏了，但目前还不能确认同步成功，下一步我再查。 | 同步暂未完成：2 个接口超时导致写入中断，已定位原因，10 分钟内重试并回传结果。 |
| **客户消息带内部腔** | 您好，经后台核查该 SKU 目前处于仓库调拨状态，不代表已丢失也不保证本周一定签收，具体以物流回执为准。 | 您好，这件商品正在仓库中转，目前物流正常。预计明天下午更新派送进度，到时我第一时间发给您确认。 |

## 四、写给人看的核心方法

| 要点 | 具体做法 |
| --- | --- |
| **一句话说清观点** | 每个主要观点用一句完整直白的话表达具体发生了什么或建议做什么，不写空泛主题词，不把多个判断挤进一个长句。 |
| **最多三项关键论据** | 每个主要观点选最重要、互不重复的 1–3 项论据；分清共同支持、先后依赖与因果关系。证据不足就收窄结论或明写缺口，不为凑三条拆同一事实或编造依据。 |
| **白话具体，非专业可读** | 写给没学过本领域专业课的大学二年级读者。用日常具体词讲清人、事、条件、动作与结果；少用“赋能、闭环、抓手、兑现”等抽象词；必要专名首次出现即用白话解释。 |
| **图表优先** | 比较、结构、先后和依赖优先用表格或流程图；表格已经讲清的，正文只说取舍不逐格复述。一句话能讲清时不强加图。 |
| **重要条件紧挨结论** | 真正改变判断的假设、缺失、费用风险与截止时间紧挨相关结论写明，不藏进附录；普通补充用标明“补充说明：”的引用块，长证据放附注。 |

## 五、事实、未知与边界的准确表达

| 实际情况 | 规范写法 |
| --- | --- |
| 已确认 / 估算 / 猜想 | 明确标注口径，不把推测写成事实；缺失或未核验绝不填 0。 |
| 要求未定 | 点明哪项边界未定，例如“尚未确定最大可承受亏损额度”。 |
| 缺事实 | 写明缺什么及谁来查，例如“缺 11 月物流实付账单，待财务补发后核算”。 |
| 待拍板 | 直接写明待谁决定什么、A/B 选项的利弊与安全边界，以及推荐项。 |
| 已知冲突 | 直指违反哪条底线，例如“测算毛利低于既定门槛，建议暂不立项”。 |

## 六、发布前 5 秒自检与审核清单

1. **只看第一屏 / 第一句**：3 秒内能否看懂核心结论、关键数字以及是否需要拍板？发给客户的消息，手机一屏能不能舒服读完？
2. **查常见失分项**：有没有把关键数字删没了？有没有内部黑话或客户不该看的内部免责？有没有复读标题？复核点是不是具体可触发时点？
3. **核对字数、三致与授权**：任务卡结论 ≤40 字、下一步 ≤30 字？标题、状态、正文是否一致，需拍板是否标「待批准」？对外消息是否严守授权口径不乱承诺？
4. **全文整理不打补丁**：更新已有文档前完整读全文，在原位置替换失效内容、清理重复与矛盾，不只在末尾追加。
5. **读回成品验收**：保存后重新打开目标页面，核对正文、表格、图、折叠区与链接，不凭「保存成功」判合格。
