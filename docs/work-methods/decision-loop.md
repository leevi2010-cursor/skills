# 决策闭环｜v1.5

决策闭环，就是先想清楚要解决什么问题、希望做到什么，再选办法去做；做完看看结果，决定继续、调整，还是停下。目标可以是达到明确结果，也可以是探索未知，两者使用同一套决策流程。

## 五步流程

| 步骤 | 要想清楚什么？ | 这一步写下什么？ |
| --- | --- | --- |
| 1 想清楚要决定什么、想做到什么、什么不能接受 | 这次要作什么决定？希望得到什么结果？哪些情况不能接受？必要时先问：我为什么要在这几个选项里选？真正要解决的是什么问题？ | 要作的决定、希望达到的结果、不能接受的情况，以及还没想清楚的部分。可以用下方表格 |
| 2 看看现在怎么样、离目标还有多远 | 现在做到了什么？有什么能力、兴趣、时间、资金、工具和人手？这些判断从哪里来？哪些是事实，哪些是估算，哪些还只是猜想？ | 离目标还差什么，以及哪些尚不知道的事情会影响选择 |
| 3 想出不同办法，必要时先小范围试一试 | 有哪些不同方向？哪些重要问题还不知道答案？能否先花少量时间或金钱试一试，而且试完发现不合适时能退回来？ | 可以选的办法、怎样试、具体怎么安排 |
| 4 先排除不能接受的办法，再比较和选择 | 先看每个办法会不会碰到不能接受的情况，再比较能帮目标做到什么程度、要花多少时间和钱、可能出什么问题 | 选什么、为什么选。要求还没想清楚，就写“还没想清楚”；缺事实信息，就写“还不知道”，并说明要弄清什么；需要用户选择，就写“等用户决定”；已经知道碰到底线，就写“这个办法不能照原样做”。没有弄清楚，不能当作已经符合要求 |
| 5 做完看看结果，再调整 | 离目标更近了吗？哪些原来的判断需要改变？有没有没想到的代价？ | 继续、调整还是停止；需要时回到前几步重新考虑。要改变目标本身，仍由用户决定 |

这套方法帮你整理做决定时要想的事，并从做过的事情中学到东西。下面的“目标和底线”表格用于第一步。具体选什么办法、怎么做、怎么检查效果，在后面几步展开。它不能替你准确预测结果，也没有被证明适合所有决定。

具体目标和最新资料仍写在各自的目标原页，本页不重复保存会变化的结果。

## 用到时再看：表格和例子

### 第一步用：目标和底线工具

目标是“希望得到什么”；底线是“什么情况不能接受”。先排除已经知道会碰到底线的办法，再比较剩下的办法能把目标做到什么程度。

每个要考虑的方面，都要分别写目标和底线。如果还没想清楚怎样判断或具体数字，就写“还没想清楚”；如果标准已经确定，但缺少实际情况，就写“还不知道”，并说明缺什么信息。需要用户选择或同意时，写“等用户决定”，不能当作已经同意。已经知道会碰到底线的办法，不能照原样做。空白或没有弄清楚，既不能当作已经符合要求，也不能直接判为不符合要求。

先写清楚看的是全部项目还是某一个项目、看多长时间、用什么单位。一个项目单独看能做，也要和现有项目放在一起，检查一共要占用多少现金、本人一共要花多少时间。

讨论目标、选择办法、同意实际投入，是不同的事。需要谁同意、已经同意做到哪一步，仍按原来的约定执行。

#### 通用模板

每个要考虑的方面，都填写以下内容。需要时可以增加要看的项目，不要为了填满表格而编数字。

| 要填什么？ | 怎样填写？ |
| --- | --- |
| 想改善哪一方面？ | 写希望改善的方面 |
| 怎么判断？用什么单位？包括哪些项目或对象？ | 写清看全部项目还是单个项目、包括什么、数字怎样计算 |
| 想做到什么？什么时候看结果？ | 写希望改善的方向或达到的数字，以及什么时候看结果；还没想清楚的部分直接写明 |
| 什么情况不能接受？怎么知道碰到了？ | 写不能接受的结果，以及出现什么情况就算碰到底线；还没想清楚的部分直接写明 |
| 现在怎么样？根据什么、哪天的资料？ | 写目前的情况或数值，标明哪些是事实、估算或猜想，并链接最初的资料 |
| 什么时候再检查？ | 写日期、检查间隔，或发生什么事后再检查；还没决定就写“还没决定” |
| 碰到底线后怎么办？谁来处理？ | 写需要暂停、调整，还是交给谁作决定，以及谁负责处理；没决定的部分写“还没决定” |

每个方面分别写目标和底线。不要把各个方面合成一个总分后，就看不出为了得到什么而放弃了什么。

长期能力既看已有的知识、工具、经验等能不能继续派上用场，也看能不能学会以后有用的新本领。判断已有的东西是否有用，要看实际用了几次、多久会用一次、每次带来了什么帮助。

具体目标、当前数字、暂时的猜想、还没想清楚的部分和判断依据，只在各自的目标原页保存和更新。本模板不写死个人数字；其他目标和项目链接原页，不另抄一套可用额度。

#### 如何整理和使用目标

1. 先读目标目录和当前目标原页，沿用已经确认的先后顺序。
2. 各领域写清自己希望得到什么结果、有哪些特别不能接受的情况。大家共用的定义、计算方法和要求，链接总目标原页。
3. 做决定时，先看会不会碰到底线，再比较能帮目标做到什么程度。什么不能接受还没想清楚，就先写出这件事，继续想清楚；底线已定，但不知道某个办法能不能满足，就补上会影响选择的信息。已经知道不满足底线的办法，不放进后面的比较。
4. 增加项目或投入后，重新检查全部项目合起来的现金和时间。不能把全部项目共用的额度，算成每个项目各自都能用的额度。
5. 有新事实或用户确认要改变目标时，更新目标原页，注明版本，并保留仍然有用的判断依据。涉及目标本身的改变，仍需用户决定。具体待办仍放在统一事项管理中。

### 第五步用：每日工作日志后的复盘

每天先写完当天的原文工作日志，再在当天记录的末尾加上以下复盘表。日期仍按从新到旧排列；不改写原文，不另建或迁移日志。本页只保存方法和空白模板，当天发生的事和对它们的判断，仍放在原工作日志。

复盘前，先看目标原页中的目标和底线。目标模板、工作方法和已经作出的决定，都可以检查是否有用、是否需要改进，不把它们当作唯一答案。每天重点看最值得改进的一件事，不为凑建议到处找资料。只有需要比较时，才查其他人或机构的相关做法，保留来源，并写清什么情况下适用。知名或流行，不能证明它更好。

#### 当日复盘｜YYYY-MM-DD

| 要回看什么？ | 今天写什么？ |
| --- | --- |
| 今天想推进什么目标？要注意什么底线？ | 链接目标原页，写今天主要想推进哪项目标、要注意哪项底线。定义、算法或要求还没想清楚的，直接写明 |
| 原来以为会怎样？实际发生了什么？ | 写事前预期，以及今天实际得到的结果、新信息和没想到的代价。附最初的资料、日期，并说明观察了哪些项目、对象或时段；分清事实、估算和猜想。做完多少事、写出多少文档，不直接等于离目标更近 |
| 对目标到底有没有帮助？ | 分别写“有帮助／有不利影响／效果还没显现／信息还不够判断”，并说明理由：离目标更近还是更远？碰到底线的可能性有没有变化？哪些原来不知道的事现在弄清楚了？预计以后会有的作用，与已经发生的效果分开写。两件事同时发生，不代表一件一定是另一件造成的 |
| 最值得改进的一件事是什么？ | 哪一步、哪个猜想或哪个已作的决定最值得重新想想？有什么事实与原来的判断不符？哪些情况不适用？漏看了什么？没有足够信息时，写清还不知道什么、需要怎样查清或试一试 |
| 换一种做法会更好吗？ | 把现在的做法和最值得考虑的一种替代做法放在一起，比较各自适合什么情况、预计能得到什么、要花什么、可能出什么问题，并给出根据或来源。没有可靠的比较结果，就写“还不知道哪种更好”，不要称为最优 |
| 建议怎么做？哪些已经同意，哪些还要确认？ | 写建议继续、调整、停止，还是请用户重新考虑之前的决定，并说明理由。建议和已同意执行的行动分开写。重要决定、目标和底线的改变，仍需用户确认，不因复盘自动修改 |
| 下一次怎么检查或试一试？ | 选一个范围尽量小、足以回答当前问题的检查或尝试：想弄清什么、谁负责、何时或发生什么事后看结果、出现什么结果说明原来的想法有道理，什么结果说明需要改变。负责人或日期还没决定的，直接写明。下次先看已经到了检查时间的事项，把结论写回原记录；还需跟进的事放进既有的统一事项管理 |

长期收益还没显现时，可以写“效果还没显现”，并说明预计什么时候能看出来。缺资料时，写“信息还不够判断”，不要编造当天的帮助。没有根据说明新办法更好时，可以先保留现在的做法，再设计一个投入较少的尝试，不为改变而改变。

#### 方法改进示例

写出了目标模板，不等于已经赚得更多或省下时间。可以在下一件真实决定中试用：做之前写预计结果和底线，做之后比较实际结果、花了多少时间、有没有带来其他问题，再决定保留、简化还是换掉模板。

这项建议参考了[IHI 官方 PDSA 测试指南](https://www.ihi.org/library/model-for-improvement/testing-changes)中先写预期、观察结果、从小范围尝试中调整做法的思路。它还需要实际试过才能判断效果，不代表已经证明比当前方法更好，也不代表已经同意投入或改变目标。
